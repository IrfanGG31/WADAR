# D5 — Layar Stock Intelligence & Financial Insight (Kam 15 Okt)
Tujuan: angka core D4 tampil di layar lewat fungsi `src/core/*` saja; narasi template deterministik (tanpa LLM); rapi di 390 px.
1. **Stok → 2 tab** (route per tab, pola Kasir · Riwayat): `stok` **Stok Produk** (daftar lama + status forecast, laju jual, habis ±hari, saran pesan) dan `stok/prediksi` **Prediksi & Rekomendasi**: kartu "Memprediksi" (`narrateForecast` item paling mendesak + ringkasan), **barang lambat laku** urut modal tertahan + total (STK-4), tabel laju/stok pengaman/titik pesan/habis dalam/status/saran pesan + filter status · kategori · "perlu restock saja" · "lambat laku".
2. **Keuangan → 3 tab**: `keuangan` **Ringkasan** (6 kartu R/C/F/S/GP/NP vs 7 hari sebelumnya, kartu **"Kenapa untung berubah?"** dari `decomposeProfitChange`, untung kotor per hari, **donut kategori**), `keuangan/margin` **Margin** (peringatan `SELL_BELOW_COST`/`FEE_HEAVY`/`DISCOUNT_HEAVY` berlabel Indonesia + "Lihat datanya", margin per kanal & per produk), `keuangan/detail` **Detail** (28 hari × R/C/F/S/GP/E/NP + total).
3. Core baru (murni + test): `stock-insight.ts` (pemetaan `forecastStock` → baris tabel, filter, lambat laku, narasi), `finance-insight.ts` (fin_daily → baris, kartu, efek + narasi, donut largest remainder, margin kanal/produk, label & kalimat peringatan, tabel harian), `period.ts`, `number-format.ts`, `formatSignedRupiah`. `finance.ts` menerima baris agregat (`gross_total`/`cost_total`) supaya `fin_daily` tidak perlu harga rata-rata pecahan.
4. DB: `src/db/stock.ts` (satu loader forecast, dipakai Beranda + Stok), `src/db/finance.ts` (fin_daily + varian + kanal + pengeluaran), `src/db/paginate.ts`. Semua di-`cache` per request.
5. Beranda: kartu **"Insight untukmu"** (SPRINT-8D D5): satu kalimat stok + satu kalimat keuangan, tautan ke layarnya.

Keputusan:
- "Minggu ini" = 7 hari bergulir (hari ini−6 … hari ini) vs 7 hari sebelumnya — sesuai cerita seed (promo gajian & porsi TikTok di 7 hari terakhir).
- Margin per produk dari `totalsByVariant` (punya margin & `cost_known_*`); `aggregateByProduct` dipakai untuk dekomposisi. Margin % hanya atas penjualan ber-HPP; tanpa HPP → "HPP belum diisi" (FIN-4).
- "Perlu restock" = status Habis/Kritis/Menipis (sama dengan hitungan "N produk perlu dipesan ulang").
- Donut: 5 kategori terbesar + "Lainnya"; persen dibagi largest remainder (selalu 100%); palet kategorikal tervalidasi, legenda berlabel + nilai = tampilan tabel.
- Angka perubahan pakai minus U+2212 (`−Rp…`) supaya tidak terpotong baris.
- `SELL_BELOW_COST` dievaluasi per baris agregat fin_daily (hari × varian × kanal), bukan per transaksi; kalimat UI menyebut unit & rugi, bukan jumlah transaksi.
- Perbaikan laten D4: `stock_daily_series` (56 hari × ±30 varian > 1000 baris) dulu terpotong diam-diam oleh batas PostgREST → sekarang dipaging (`.order().range()`).
