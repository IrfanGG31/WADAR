## Unit 3 — Cache DEMO_SAFE
`src/core/consult/cache.ts` (murni): `createTtlCache` (LRU 200 entri, TTL 1 jam), `dataVersion` (sha256 atas seluruh `ConsultData`), `askCacheKey` (tenant + versi data + pertanyaan ternormalisasi + deep/fast + riwayat), `weeklyCacheKey`.
Dipasang di `createConsult` (`ask` dan `narrateWeekly`; `AskRequest.cacheScope` = id toko, tanpa itu tidak ada cache):
- **Tulis:** jawaban model yang lolos grounding; jawaban templat offline hanya saat `DEMO_SAFE`. Templat pengganti draf yang gagal grounding **tidak** disimpan.
- **Baca:** hanya saat model tidak bisa menjawab (`DEMO_SAFE`, tanpa kunci, circuit terbuka) atau model error/timeout. Selama model hidup, jawaban tetap segar dan tercatat di `ai_runs`.
- **Invalidasi:** versi data ada di kunci, jadi penjualan, mutasi stok, memori baru, atau pergantian hari otomatis tidak cocok; TTL hanya membatasi umur. `clearCache()` dipanggil saat reset demo.
- Hasil cache berlabel `cached: true` ("Jawaban tersimpan · data belum berubah" di UI), `attempts` kosong → tidak ada baris `ai_runs` dan tidak menghitung kuota deep. Tidak ada jawaban tertulis di kode.
- Keterbatasan: cache ada di memori **per instance** serverless (seperti breaker). Di Vercel, permintaan yang jatuh ke instance lain tidak kena cache; untuk demo, pemanasan lewat `/api/consult` di instance yang sama tidak dijamin. Cache bersama (tabel/KV) masuk backlog.
